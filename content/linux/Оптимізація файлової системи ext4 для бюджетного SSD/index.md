Якщо операційна система встановлена на бюджетний SSD, можна оптимізувати параметри монтування файлової системи **ext4**. Це допоможе зменшити кількість зайвих операцій запису, знизити навантаження на накопичувач і зробити систему більш плавною.

## Що змінюється

| Параметр | Типове значення | Оптимізоване значення | Для чого це потрібно |
|----------|-----------------|-----------------------|----------------------|
| Параметри монтування | `defaults` | `defaults,noatime,commit=60,discard` | Зменшує кількість фонових записів і навантаження на SSD. |
| Запис часу доступу (`atime`) | Записується після кожного читання файлу | `noatime` | Скасовує тисячі непотрібних операцій запису під час запуску програм та ігор. |
| Інтервал запису журналу (`commit`) | `commit=5` | `commit=60` | Зменшує частоту скидання кешу на диск, що може знизити мікрофризи під навантаженням. |
| Очищення блоків (`TRIM`) | Виконується періодично | `discard` | Автоматично повідомляє SSD про видалені блоки для підтримки стабільної швидкості запису. |

## Приклад налаштування `/etc/fstab`

> [!IMPORTANT]
> Перед внесенням змін рекомендується створити резервну копію файлу `/etc/fstab`.

Приклад конфігурації:

```fstab
UUID=12345678-1234-1234-1234-123456789abc / ext4 defaults,noatime,commit=60,discard 1 1
UUID=87654321-4321-4321-4321-cba987654321 /boot ext4 defaults,noatime 1 2
UUID=ABCD-1234 /boot/efi vfat umask=0077,shortname=winnt,nofail,x-systemd.device-timeout=2 0 2
```

## Застосування змін

Після збереження файлу виконайте:

```bash
sudo systemctl daemon-reload
sudo mount -o remount /
```

> [!TIP]
> Якщо команда `mount -o remount /` завершується помилкою або деякі параметри не застосувалися, просто перезавантажте комп'ютер.

> [!NOTE]
> Параметр `discard` забезпечує безперервний TRIM. На сучасних SSD він зазвичай працює без проблем, однак деякі користувачі віддають перевагу періодичному TRIM через `fstrim.timer`. Обидва варіанти є робочими.
